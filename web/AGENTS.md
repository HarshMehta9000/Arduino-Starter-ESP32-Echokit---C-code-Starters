# Handoff: the smart_led teardown

An interactive teardown of the two firmware files in `../firmware/`. Read this
before changing anything here. Next 16 needs Node 20.9 or newer.

## The one rule that governs this codebase

**Every number on the page is recomputed from the real firmware. Nothing is
transcribed.**

That is not a style preference, it is what makes the site worth anything. A
teardown that quotes numbers a human typed is a blog post with extra steps. So:

- `src/lib/source.ts` is **generated** from `../firmware/*` by
  `npm run gen:source`. Never hand-edit it. Rerun the script when the firmware
  changes.
- Line counts, diff statistics and severity tallies are derived
  (`DIFF_STATS`, `SEVERITY_COUNTS`), never written down. The page metadata in
  `src/app/layout.tsx` imports `DIFF_STATS` for the same reason.
- Findings in `src/lib/findings.ts` locate their line numbers with
  `findLine(lines, needle)`, so a citation follows the code when it moves
  rather than silently pointing at the wrong line.
- `SERIAL_CLAIM_HOLDS` and `CPP_HAS_SERIAL_LOG` are **computed** from the
  sources. The claim that the C++ port drops serial logging is checked, not
  asserted.

If you add a claim to the page, add the computation that backs it.

## The firmware port

`src/lib/firmware.ts` is a line-for-line port of `smart_led.ino`. Two details
in it are load-bearing and easy to "fix" by mistake:

1. **`arduinoMap` truncates.** Arduino's `map()` is integer math. Rounding
   instead of truncating changes the result at 510 of the 1024 knob positions.
   `Math.trunc` is deliberate.
2. **`step()` models the `delay(50)` stall** via `stallUntil`. The sketch calls
   a blocking delay in the button branch, and the page's whole argument about
   non-blocking timing depends on showing that, not skipping it.

`step()` also deliberately does **not** adapt to the board's ADC width. That is
the bug the port lab exists to demonstrate, so the function must stay naive.

Guarded by `npm run verify:port`: 3080 assertions against an independent
reference built on truncating BigInt division, covering all 1024 pot positions,
both endpoints, monotonicity, and the ESP32 full-scale result of 3702ms. Run it
after touching anything in `firmware.ts`.

## Shared state

`src/lib/sim.tsx` runs one `requestAnimationFrame` loop for the entire page.
Every interactive element reads it, which is why the hero board blinks on the
same schedule as the bench trace. Notes:

- The render body stays pure. Refs are synced inside a dep-less `useEffect`,
  not assigned during render. The React Compiler lint rules will fail the build
  if you regress this.
- `setBoardId` is a `useCallback` that clamps the pot, rather than an effect
  that calls `setState`, for the same reason.

## The 3D board

`src/lib/board-spec.ts` holds the real ESP32-WROOM-32S NodeMCU-32S mechanical
figures **in millimetres**. `Board3DScene.tsx` multiplies by `MM`. Keep the
spec in real units so proportions cannot drift, and change the spec rather than
the renderer.

Textures in `src/lib/silkscreen.ts` are generated onto a canvas at runtime.
Environment lighting uses `<Lightformer>` rather than an HDR file. Both exist so
the page fetches nothing from a CDN. Do not introduce a remote asset.

The scene is imported through `BoardCanvas.tsx` with `ssr: false`. There is no
browser on the build machine, so a successful production build is the only
compile-level check available for it.

## Media

`docs/media/*` is generated by `npm run media`, not captured. The build machine
has no browser and no ffmpeg. `scripts/gen-media.mjs` compiles `firmware.ts`
and `board-spec.ts` with `tsc` into `.media-build/`, then draws every frame
with `@napi-rs/canvas` against the real `step()` loop at 1ms resolution. Output
is mirrored into `public/media/` so Next can serve it.

GIFs use a single global palette plus inter-frame differencing, with palette
index 255 reserved as transparent and `dispose: 1`. That is what takes the
bench clip from 2.2MB to 430KB. Keep `maxColors` at 255 or the transparent
index collides with a real colour.

To inspect a frame without a browser, render it with `encodePng` from
`scripts/lib/gif.mjs` and open the PNG.

```bash
npx tsc --noEmit
npx eslint src scripts
npm run verify:port
npm run build
```

## House style

- **No em dashes and no en dashes anywhere.** Site copy, README, commit
  messages. This is a hard requirement from the repository owner. The block at
  the top of this file is scaffolding from `create-next-app` and is the one
  exception, left verbatim so tooling can match on it.
- Dark instrument-panel palette, defined once in the `@theme` block of
  `src/app/globals.css`. One brand accent (amber), one data accent (cyan), one
  alarm (red). Do not add a fourth.
- Prose states what the code does and what it costs. No marketing verbs, no
  claims the page cannot back with a computation.
